# Commands

Purpose
- Explain how command registries work and where to find them.

Quick start
- Generate registries:
  `python context_compass/workspace/tools/general/command_registry_generate.py --repo-root . --agent-id <agent_id> --work-id <work_id> [--manifest-path <path>]`
- Describe commands without SQL (path-safe):
  `python context_compass/workspace/tools/general/command_registry_describe.py --repo-root . --agent-id <agent_id> --actor-id <actor_id> --scope user`
- Describe ToolCommandAPI registry entries (full details):
  `python context_compass/workspace/tools/general/tool_registry_describe.py --repo-root . --agent-id <agent_id> --work-id <work_id> --scope both`
- Describe SQL registries (full details):
  `python context_compass/workspace/tools/sql/crud/sql_command_registry_describe.py --repo-root . --agent-id <agent_id> --work-id <work_id> --scope all`
  `python context_compass/workspace/tools/sql/query/sql_query_command_registry_describe.py --repo-root . --agent-id <agent_id> --work-id <work_id> --scope all`

Registry tables (source of truth)
- System registry: `command_registry_system` in `context_compass/system/storage/sqlite/system.db`
- User registry: `command_registry_user` in `context_compass/system/storage/sqlite/user.db`
- Schema: `context_compass/system/schemas/command_registry.tables.json`

Execution (non-SQL commands)
- Commands are executed through ToolCommandAPI so hooks can run.
- CLI entrypoint (recommended): `python context_compass/workspace/tools/general/tool_execute.py --command-name <name> --payload-json '{}' --repo-root . --agent-id <agent_id> [--work-id <work_id>]`
- Use `command_registry_describe` or `tool_registry_describe` to discover payload fields for each command.
- Direct tool execution is allowed only as a last resort and bypasses hooks.
- SQL CRUD/query scripts are DB-only and never run hooks.

Execution (SQL tools)
- CRUD execution: `python context_compass/workspace/tools/sql/crud/sql_crud_execute.py --repo-root . --agent-id <agent_id> --work-id <work_id> --operation read --scope user --table-name <table> --action <action> --actor-id <agent_id>`
- Query execution: `python context_compass/workspace/tools/sql/query/sql_query_execute.py --repo-root . --agent-id <agent_id> --work-id <work_id> --scope user --query-name <name> --actor-id <agent_id>`

Generation
- Registries are machine-owned and generated by:
  `python context_compass/workspace/tools/general/command_registry_generate.py --repo-root . --agent-id <agent_id> --work-id <work_id> [--manifest-path <path>]`
- Default manifest path: `python context_compass/workspace/tools/general/command_registry_path.py --repo-root .`
- Use `--manifest-path` to override the manifest location.
- Add `--export-json` to emit JSON files under `context_compass/commands/`.
- Use `--export-dir` to override the export directory.
- Describe entries with:
  `python context_compass/workspace/tools/general/command_registry_describe.py --repo-root . --agent-id <agent_id> --actor-id <actor_id> --scope user --command-name <name>`

How to use
- Query the user registry table for the user-facing command list.
- Query the system registry table for the full agent toolset.
- Commands may still be blocked by feature flags or repo_state.
- Use tool_registry_describe for full command details (including script paths).
- Use sql_command_registry_describe and sql_query_command_registry_describe for database tool discovery.

Notes
- Optional JSON exports may live under `context_compass/commands/`.
- Exports are not generated by default.
- Workspace tools under `context_compass/workspace/tools/` are the only supported entrypoints for agents.
