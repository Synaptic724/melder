# work_management

Purpose
- Define the intake and execution flow for Epics, Stories, and Tasks.
- Keep GitHub intake separate from machine-owned work queues.

Locations
- context_compass/user/github_intake/tickets/: raw GitHub tickets as .md files.
- SQLite user.db tables `work_queues` and `work_queue_items` store global queues (scope=global, branch_name null).
- SQLite user.db tables `work_queues` and `work_queue_items` store branch queues (scope=branch, branch_name set).

Format
- Queue payloads are stored in SQLite using the tasks.schema.json shape.
- Payloads are expressed as JSON at command boundaries and persisted as relational rows.
- Work items use work_id (uniform id for epics/stories/tasks) and must include kind.
- Work ids are auto-generated by tooling when omitted (8-char alphanumeric).
- parent_work_id and root_work_id are required for all items (use null for top-level).

Workflow
1) Copilot drops new ticket into context_compass/user/github_intake/tickets/.
2) Human or agent triage moves ticket into branch backlog.
3) Break Epic -> Story -> Task inside backlog.
4) Move items into ready when they are approved to start.
5) Move ready items into active when work begins.
6) Move items to completed or denied when finished.
7) Promote branch work items to global queues when you want shared history.

Tooling
- Use ToolCommandAPI command `work_item_add` to create epics/stories/tasks in any bucket.
- payload field ticket_path can be supplied to tie the work item back to the intake markdown.
- Use ToolCommandAPI command `work_item_move` to move items between ready/backlog/active/completed/denied.
- Use ToolCommandAPI command `ticket_promote` to create a root epic/story/task from a ticket, with optional child_items payload.
- Use ToolCommandAPI command `work_item_close` to move items to completed/denied and clear per-agent queues.
- Use ToolCommandAPI command `work_item_global_to_branch` to pull global items into the active branch.
- Use ToolCommandAPI command `work_item_branch_to_global` to publish branch items to the global history.
- Use ToolCommandAPI command `work_item_agent_to_branch` to move agent-owned items into branch queues.
- Use ToolCommandAPI command `work_item_agent_to_global` to move agent-owned items into global queues.

Lineage rules
- story items must include parent_work_id (they cannot be root items).
- tasks may be root or child; when derived from an epic/story they must set parent_work_id and root_work_id.

Locking
- Any write to branch or global queues requires a lease lock in system.db (resource scoped to the queue).
- Re-read latest state after acquiring a lock and before writing.

Notes
- The scanner emits tasks into the ready branch queue.
- Work queue tooling requires work_management feature enabled in SQLite `config_context_compass_*` tables.
- If work_mode is hard, tools require a work_id for each work action.
