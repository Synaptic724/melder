# system_doc_index_generation

## Purpose

Define how to CRAFT a line-range index over one large system document, so an agent can
slice the sections it needs instead of reading the whole file.

The index is a map from heading to line range. It carries no prose of its own. Its only
job is to let a consumer answer "which lines do I read?" and then read exactly those.

## Why this exists

`src_components.md` is ~5,176 lines and `src_architecture.md` ~2,079. Measured against
the live onboarding readset, those two files are ~102k of ~232k tokens - 44% of the
entire cost in two files. Most lanes need one subsystem, not all of them.

## When To Use

- An indexed document was edited, so its index is stale.
- A document is being indexed for the first time.
- A consumer reported an index-staleness refusal (see `system_doc_index_usage.md`).

Do NOT use this to index small documents. Below roughly 400 lines the index costs more
attention than the read it saves.

## THE STALENESS CONTRACT (read this first)

A line-offset index is more fragile than the prose it indexes. Insert one line near the
top and every range below it is wrong - while the index still parses, still looks
plausible, and still returns content. It returns the WRONG content, confidently.

This is not hypothetical. In this repository a derived inventory over these same
documents drifted twice within hours (the C1 Code Map, generated at 550 modules, silently
became wrong at 553) and nobody noticed until a human asked.

Therefore an index is only trustworthy if it can be PROVEN current, and it must carry
the proof itself:

- `line_count` - total lines in the indexed document at generation time.
- `content_sha256` - SHA256 of the document's exact bytes at generation time.
- `line_ending` - `crlf` or `lf`, because a consumer that splits on the wrong terminator
  computes different line numbers than the generator did.

A consumer recomputes all three and refuses to slice on any mismatch. An index without
these fields is not a weaker index, it is an unusable one. Never emit a partial header.

## Required Contract

- Source: one Markdown document under `system_docs/`.
- Output: one JSON file beside it, named `<document_stem>_index.json`.
  - `src_architecture.md` -> `src_architecture_index.json`
  - `src_components.md` -> `src_components_index.json`
- The index is DERIVED. It is regenerated by re-walking the document, never edited by
  hand. Hand-editing a range is how an index starts lying.
- Line numbers are 1-BASED and INCLUSIVE on both ends, matching `sed -n 'S,Ep'`, the
  `Read` tool's offset/limit, and this repository's existing
  `path:start_line-end_line` evidence convention. Do not invent a different basis.
- A section's range runs from its own heading line to the line before the next heading
  of the SAME OR SHALLOWER depth, or to end-of-file for the last section.
- Fenced code blocks are skipped when detecting headings. A `#` inside a fence is not a
  heading, and treating it as one produces ranges that split a code example in half.
- **The document TITLE is omitted.** A lone `#` heading is the document's name, not a
  navigable section, and its range necessarily spans almost the entire file. Both target
  documents have exactly one: emitting it produced a "section" of 5,174 of 5,176 lines -
  an entry whose only possible use is to defeat the index while appearing to use it.
  Omit any heading at the minimum level present when only one exists at that level.

## Index Schema

```json
{
  "index_version": "1.0.0",
  "document": "system_docs/src_components.md",
  "generated_at": "2026-07-26T17:13:51Z",
  "line_count": 5176,
  "line_ending": "crlf",
  "content_sha256": "<64 hex chars>",
  "sections": [
    {"level": 2, "path": "C3 Components Catalog", "start": 174, "end": 2140},
    {"level": 3, "path": "C3 Components Catalog > Component: Spellbook Core", "start": 290, "end": 363}
  ]
}
```

Field notes:

- FOUR fields per section, and no more. The index is a lookup table, not a summary; every
  byte of it is paid on every read.
- `path` is the breadcrumb of ancestor titles joined by ` > `. This is what makes an
  index searchable by subsystem: a consumer greps `path` for `crystallizer` and gets
  every range that matters without knowing the heading hierarchy in advance.
- There is deliberately NO `title` field - it is `path.split(" > ")[-1]`. There is
  deliberately NO `lines` field - it is `end - start + 1`. Both were in an earlier draft
  and measured at 3,900 tokens of pure redundancy on `src_components.md` alone.
- Emit COMPACT JSON (`separators=(",", ":")`, no indent). Pretty-printing the components
  index costs ~1,400 tokens for whitespace nobody reads.
- Nested sections are emitted ALONGSIDE their parents, not instead of them. A consumer
  may want the whole catalog or one component; both ranges are valid answers.
- `index_version` gates the schema. A consumer refuses a MAJOR it does not know.

### Index cost, measured

An index is not free, and it should be sized honestly against the read it replaces:

| document | document | index | index as % |
|---|---|---|---|
| `src_architecture.md` | ~30,100 tokens | ~2,100 | 7% |
| `src_components.md` | ~72,100 tokens | ~5,600 | 8% |

That overhead is worth paying when a lane needs one or a few sections, which is the
normal case. It is NOT worth paying when the lane needs the whole document - in that
case, skip the index and read the file.

## Generation Recipe

Keep this recipe in Markdown. Do not commit a generation script - this follows the
existing precedent in `graph_details_readable_generation.md`, where the recipe lives in
the skill and is run inline.

```python
import hashlib, json, re, pathlib, datetime

DOC = pathlib.Path("context_compass/system_docs/src_components.md")

raw_bytes = DOC.read_bytes()
raw = raw_bytes.decode("utf-8")
nl = "\r\n" if b"\r\n" in raw_bytes else "\n"
lines = raw.split(nl)
if lines and lines[-1] == "":
    lines.pop()                       # trailing terminator is not a line

heading = re.compile(r"^(#{1,6})\s+(.*?)\s*$")
fence = re.compile(r"^\s*(?:`{3}|~{3})")   # quantified, so this line is fence-safe

found, in_fence = [], False
for i, line in enumerate(lines, start=1):
    if fence.match(line):
        in_fence = not in_fence
        continue
    if in_fence:
        continue
    m = heading.match(line)
    if m:
        found.append((i, len(m.group(1)), m.group(2)))

levels = [lv for _, lv, _ in found]
min_level = min(levels) if levels else 1
skip_title = levels.count(min_level) == 1          # lone top heading is the title

sections, stack = [], []
for idx, (start, level, title) in enumerate(found):
    end = len(lines)
    for nxt_start, nxt_level, _ in found[idx + 1:]:
        if nxt_level <= level:
            end = nxt_start - 1
            break
    while stack and stack[-1][0] >= level:
        stack.pop()
    crumb = " > ".join([t for _, t in stack] + [title])
    stack.append((level, title))
    if skip_title and level == min_level:
        continue                                   # document title, not a section
    sections.append({"level": level, "path": crumb, "start": start, "end": end})

index = {
    "index_version": "1.0.0",
    "document": DOC.as_posix().split("context_compass/", 1)[-1],
    "generated_at": datetime.datetime.now(datetime.timezone.utc)
                        .strftime("%Y-%m-%dT%H:%M:%SZ"),
    "line_count": len(lines),
    "line_ending": "crlf" if nl == "\r\n" else "lf",
    "content_sha256": hashlib.sha256(raw_bytes).hexdigest(),
    "sections": sections,
}

out = DOC.with_name(DOC.stem + "_index.json")
out.write_text(json.dumps(index, separators=(",", ":")) + "\n",
               encoding="utf-8", newline="\n")
print(f"{out.name}: {len(sections)} sections over {len(lines)} lines, "
      f"{out.stat().st_size:,} bytes")
```

## Validation

Every generated index must pass all four before it is accepted:

1. **Round trip.** For a sample of sections, slice `lines[start-1:end]` and confirm the
   first sliced line is the heading named in `title`. This catches an off-by-one
   immediately, and an off-by-one is the failure mode that silently corrupts every
   downstream read.
2. **Coverage.** The union of the shallowest EMITTED level's ranges must cover every line
   from the first emitted heading to `line_count` with no gaps and no overlaps. Since the
   title is omitted, that is normally `level` 2.
3. **Monotonicity.** `start` values strictly increase in emission order, and every
   section satisfies `start <= end <= line_count`.
4. **Fingerprint.** Recomputing `content_sha256` over the document reproduces the stored
   value. If the document changed during generation, discard and regenerate.

## Handoff Rule

When an index is generated, report:

- document indexed, and its line count
- output path
- section count, and the deepest heading level captured
- largest single section in lines, since that is what a consumer will have to chunk
- whether all four validations passed

## Anti-Patterns

- Hand-editing a range in a generated index.
- Emitting an index without `line_count`, `content_sha256`, and `line_ending`.
- Indexing a document you also edited in the same pass without regenerating afterwards.
- Detecting headings without fence awareness.
- Using 0-based or exclusive-end line numbers, which silently disagree with every other
  line reference in this repository.
- Committing a generation script rather than running the recipe inline.
