# Named publication and resolution control flow

## Named Acquisition
Within existing parent then child lock: attach Ward, register Cloud, emit structural twin, publish
the current Nexus conduit record and frame overview. Post-created callbacks run afterward. Suppress
the old fresh-only publication tail for named calls so callback-triggered cleanup/reuse cannot publish
a stale use afterward. Ordinary unnamed allocation keeps its current publication path.

## Named Soft Return
Under the existing child cleanup lock: finish descendants; emit retirement; publish pooled values for
the existing Nexus record; unregister this identity from Cloud; refresh frame summary; clear name;
detach Ward. Shared pool preparation then sets physical pooled status, restores hooks and publishes
idle. No new unnamed flag, lock, scan or sink call. Retry uses the retained name until all fallible
publication work succeeds. Existing conditional hard cleanup also refreshes the Cloud summary.

## Named Getter
Check raw/frame access; select published ID by name; resolve that ID through existing ACL-checked
root/lesser traversal; compare live name with requested name and refuse if it changed. Never resolve
the runtime by name after authorizing a different identity. No extra retained reference/index/lease.

## Non-Goals
Do not automatically refresh inside an active Rift gate, alter static raw access, admit lesser roots
into bind/link/cluster operations, or revise ordinary anonymous scope observation.
