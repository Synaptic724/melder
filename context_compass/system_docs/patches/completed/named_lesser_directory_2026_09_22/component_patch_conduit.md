# Lesser acquisition, retirement and promotion

## Acquisition
Validate a supplied name before hooks or shell acquisition. Fresh and reused shells receive it before
activation. Named attachment takes the existing narrow parent window and the unpublished child's lock,
then publishes to Cloud. On failed admission, recycle the unpublished shell through normal cleanup.
Advisory hook exceptions retain their existing behavior. Hook-driven cleanup before attachment refuses
the named acquire instead of publishing a pooled/cleaned shell. Post-created observes linked discovery.
Unnamed acquisition retains existing mechanics; no lifecycle lock broadening for its ordinary path.
Named creation refuses an already pooled parent and rechecks that state at attachment, so a hook
that returns its parent cannot publish a discoverable child beneath an idle shell.

## Return and Destruction
After existing disposal and ward detach, test _name once. When non-None, remove its named entry and
clear _name, then proceed to existing pooled status/hook restoration/idle publication. Unnamed cleanup
does no Cloud work. Disposal failure before this point leaves the scope named for an explicit retry.
Hard lesser cleanup removes discovery before deleting collaborators. Overflow sees an already unnamed shell.
The public name setter refuses lesser and pooled states; naming remains creation-only.

## Promotion
Claim the target name before gate/setup work and release it in finally. Claims accept the same id;
all competing root/lesser admissions reject them. Preserve the original live directory entry until
the frame registration bridge commits the new root name. Both private Book name checks use Cloud's
same-identity-aware admission probe. Existing rollback restores the old label; the old entry never moved.
No Spellbook, hook, creation or gate ownership redesign is included.

## Validation
Fresh/prewarmed A -> B -> unnamed reuse; nested/root cleanup; collisions; advisory and cleanup hooks;
disposal failure/retry; pool overflow; same-name and renamed promotion; pre-attachment failure/retry;
post-attachment failure cleanup; no directory calls or lock on unnamed return.
