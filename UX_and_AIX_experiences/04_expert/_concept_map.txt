ARC B COMPLETE (lessons 07-09)

  10 deep_overrides_paths_through_a_graph (advanced 19's grammar at DEPTH
     FOUR, where it stops being convenience. A PATH WALKS SOCKET NAMES,
     NOT TYPES - "gateway>upstream>credentials" is parameter names on the
     class at each level, so two sockets of the SAME type at different
     depths are DIFFERENT ADDRESSES. Four things depth changes: ambiguity
     becomes normal so `*param` starts refusing; a path that stops early
     GRAFTS A SUBTREE rather than patching a leaf; exact path BEATS
     broadcast on a shared socket, which is how you say "all of them
     except this one" in one call; a typo'd path REFUSES instead of
     applying to the nearest match)

  11 pointing_a_rift_at_your_own_frame (finishes what advanced 09 stopped
     short of - AR targeting was genuinely unreachable from `import
     melder` until 2026-08-03. The chain, every link a refusal point:
     posture -> conjure -> activate -> create_rift -> create_frame_link.
     THREE GATES IN ORDER: rift_enabled ALWAYS; ai_native and dynamic for
     CODEGEN rooms only - so the same frame is ACCEPTED by a capability
     room and REFUSED by a codegen one. rift_enabled defaults False
     because it is the frame's OPT-IN TO BEING OBSERVED, and conjure
     freezes it for the frame's whole life. ATTACHMENT IS THE AUTHORITY
     BOUNDARY: checked once, there, and never again)

  12 the_codegen_loop_end_to_end (A REFUSAL IS A RETURN VALUE, NOT AN
     EXCEPTION - validate_codegen hands back a CodegenValidationResult,
     and execute on rejected code returns a VALIDATION-FAILED
     CodegenExecutionResult without reaching compile or exec. ValueError
     is reserved for MALFORMED REQUESTS (empty code, empty frame name):
     bad input raises, bad code reports. execute VALIDATES FIRST anyway,
     so the separate verb buys the answer early and never a way around
     it - the only reason an agent can probe a boundary without crossing
     it. Seven strategies; read `recursive_control` twice - it exists
     because generated code that generates code is how a bounded system
     stops being bounded. MEMORY IS A ROOM SYSTEM AND IT PUSHES:
     room.memory_system.register_memory_callback(fn); `memory_enabled` is
     literally "is anyone listening". ONE RECORD PER SUCCESSFUL TOP-LEVEL
     CALL - refusals do not emit, and a call-depth counter suppresses
     nested emission. research_preview needs a LIVE MutationResearch: the
     research family uses a NON-CONSTRUCTING peek and refuses rather than
     booting one behind your back)

  13 one_workshop_many_worlds (one codegen room, THREE postured frames,
     two attached - where frame_name stops looking like ceremony. A
     default would not be a convenience, it would be a coin flip with
     side effects. Attachment is PER FRAME and there is no
     attach-to-everything verb, because there is no honest way to ask for
     that. list_accessible_non_nexus_frame_names(rift_id) lets an agent
     ENUMERATE ITS OWN REACH instead of probing by attempting - and note
     eligibility is not attachment, the two-bit law again. The frames
     stay walled: a shared observer is not a shared world)

  14 compositions_a_subsystem_as_one_unit (03 answered "where is this
     one"; this answers "what is our billing subsystem", which needs a
     different kind of thing - a SET someone named. EIGHT VERBS, SIX
     READS TWO WRITES, and the split is the lesson: a capability room
     reads the ENTIRE composition record and cannot change one thing in
     it. THE ID IS THE MEMBERSHIP - sha256 over the sorted, deduped
     member list - so a composition is a SET (order and duplicates
     canonicalise away), THE SAME ROSTER IS THE SAME COMPOSITION, and
     re-declaring one REFUSES as a rediscovery naming the holding lane.
     A recompose that resolves back to the previous roster refuses for
     the same reason: melder will not write "nothing happened" into a
     timeline. Recompose is FORWARD-ONLY - new node,
     parent_group_ids=[previous], SAME lane, previous untouched. Both
     writes return a describe() PAYLOAD (a detached plain dict), not the
     node. Compositions do not NEST. research_impact on a single spell
     names the subsystems it touches under affected_compositions)

  15 campaigns_the_why_that_rides_along (a lane is WHERE work lives; a
     campaign is WHICH EFFORT it belonged to, and it crosses lanes,
     subsystems, and agents. THE ONE THING TO LEARN: campaign=None DOES
     NOT MEAN "no campaign", IT MEANS INHERIT - to record with none you
     must CLEAR the ambient stamp first. Reads like a trap until you see
     what it buys: attribution defaults to TRUE rather than to blank,
     over a session of thousands of calls nobody wants to annotate. An
     EXPLICIT campaign still wins, so it is a default and not a cage. IT
     RIDES EXACTLY FOUR SEAMS, all on the ROOT FACADE -
     record_world_entry, record_promotion, register_group,
     recompose_group. The room's organizational verbs (create_lane,
     attach, archive) delegate straight to the set and are UNSTAMPED:
     moving furniture is not part of an effort's story unless you say so.
     WRITE/READ AGREEMENT IS A LAW (BUG-047): an empty campaign is
     refused on the WRITE side because campaign_view refuses it on the
     READ side - a public write may never create a record the public
     query API cannot reach. The view answers {campaign, nodes,
     transitions, lane_names} and TRANSITIONS IS THE WIDER SET: only four
     acts contribute a node, so a campaign of pure organizational moves
     yields an empty node list, which is correct rather than a gap.
     Sequenced by JOURNAL order, never a lane walk - lane iteration
     tie-breaks same-millisecond ULIDs on their RANDOM component, and a
     history that reorders itself between runs is not a history)

THE THROUGH-LINES, AT EXPERT GRAIN (both inherited from advanced)

  TWO BITS, NEVER ONE
      11  eligible to be targeted / actually attached
      14  a composition EXISTS / it is the CURRENT one for its lane
      15  a stamp is SET / a record inherited it
  Presence never implies liveness, and reach never implies grant.

  MELDER NEVER SUBSTITUTES
      10  a typo'd override path REFUSES; it does not hit the nearest
          socket, and at depth four that would be undetectable
      12  a rejected validation returns a VERDICT; it does not run a
          safer version of your code
      14  a rediscovery REFUSES; you cannot end up with two names for
          one subsystem
      15  an empty campaign REFUSES ON THE WRITE because the READ cannot
          address it
  The 15 case is the sharpest statement of it in the library: melder
  would rather fail your write than let you create a fact that nobody
  can ever ask a question about.
