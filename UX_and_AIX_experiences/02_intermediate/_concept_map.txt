LAWS PROVEN IN THIS TIER (harness-validated, run 3-4)
  - SETTLE-THEN-INHERIT: first conjure(dynamic=True) settles the world
    and locks it; later books plain-conjure and INHERIT
  - SHARING IS A PULL: X.add_spell_to_contract(spell_id=S, conduit=Y)
    means X pulls S from Y; the named conduit must OWN the spell
  - SPELLCONTRACT ORDER OF OPERATIONS (per edge): conjure provider ->
    conjure consumer -> link AFTER both -> pull -> MELD after the fact;
    chains assemble edge by edge in dependency order
  - ONE ACTIVE SPELL PER (spellframe, binding_name) SIGNATURE per frame
    (collection-DI providers need distinct binding names)
  - CLUSTERS: contracts ride LINKS (link members first); the shared
    store belongs to an ELECTED LEADER (elect before members join);
    cluster-shared spells bind with permissions="create"
  - NORMAL CODE ONLY: user flow is link / add_spell_to_contract / meld -
    never mediator transactions in curriculum code
