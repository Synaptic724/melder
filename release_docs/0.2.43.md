## Suggested release summary

Melder 0.2.43 adds registered definitions that agents can inspect and version without allowing
Melder to resolve them. It also fixes constructor-default handling, Python 3.14 deferred annotations,
existing-instance dependency planning, and provider-artifact ownership during validation.

Applications upgrading from 0.2.37 should review defaulted dependency parameters and Crystallizer
record compatibility. Existing bindings remain resolvable unless explicitly registered otherwise.

## Added

- **Non-resolvable registrations.** `bind(..., resolvable=False)` and
  `bind_inactive(..., resolvable=False)` retain a definition in Melder's registered world without
  permitting direct resolution or reuse through Meld. The default is `resolvable=True`.
- **Definitions remain useful to agents.** Abstract bases, internal helpers and explicitly
  non-resolvable Protocol definitions can retain registration identity and participate in existing
  source/history/version workflows without becoming automatic construction targets.
- **References remain visible without construction edges.** Required consumer inputs selecting a
  non-resolvable definition retain descriptive target relationships. Callers supply their values
  through existing overrides. Ordinary missing-argument errors remain Python's responsibility;
  this feature adds no runtime argument preflight.
- **Nexus relationship navigation.** `describe_spell_relationships` on ViewSpell/FrameViewer exposes
  visible incoming and outgoing dependency, supplied-reference and registered direct-base links.
  Existing ACL visibility applies to both endpoints. External changes retain the normal explicit
  Rift projection-refresh requirement.
- **Crystallizer preserves resolution policy.** SpellCrystal capture, active/staged restore and
  supported graft paths retain each version's `resolvable` value. Replayed bindings reconstruct
  their relationships through the existing compilation process.

## Fixed

- **Ordinary Python defaults are honored.** A matching registered provider no longer replaces an
  ordinary constructor default such as `None`, `0`, `False`, a collection or a chosen instance.
  Explicit SpellMap/SpellContract descriptors keep their DI meaning; explicit overrides still work.
- **Python 3.14 deferred annotations survive inspection.** Binding and dependency inspection retain
  unresolved names as ForwardRefs instead of failing immediately when annotation evaluation meets
  a name imported only under `TYPE_CHECKING`. Existing normalization/provider matching handles the
  reference; missing providers still follow normal validation rules.
- **Existing instances work as dependency providers.** Planning no longer tries to inspect a
  supplied, non-callable object as a constructor. Direct and nested consumers can receive the same
  registered reference. This repair does not introduce new instance lifetimes or ownership modes.
- **Protocol admission checks the supplied object.** Binding an existing object under a Protocol
  now checks the actual value for the supported directly declared public members and callability.
  Instance-only members and non-callable shadows are handled at bind time. This is not a full
  static type checker or a new inherited-Protocol/signature-validation system.
- **Borrower validation preserves provider execution artifacts.** Compiling a borrower or a local
  consumer no longer clears executable artifacts on providers that the pass will not rebuild.
  Provider instances and their retained state remain usable afterward.
- **Local revalidation uses the current cancellation event.** Local Phase-5/6 calls no longer capture
  the previous scheduler run's event. A failed run cannot poison the next validation, while
  cancellation during the current run still reaches the phase body.

## Upgrade notes

### Defaulted parameters now keep their defaults

Code that relied on Melder overriding an ordinary Python default must express its injection intent
explicitly. For example:

```python
# Retains None, even if Service has a registered provider.
def __init__(self, service: Optional[Service] = None):
    ...

# Requests annotation-based injection.
def __init__(self, service: Service):
    ...
```

Use an explicit SpellMap/SpellContract where that descriptor's semantics are intended, or pass a
per-call `override`. Do not make an argument nullable solely to represent required caller supply.

### Crystallizer record format advances to 2.0.0

The record format's major version changes from **1.0.0 to 2.0.0**, independently of Melder's package
version. Older readers must reject new records rather than silently discard `resolvable=False`
and turn a definition into a resolution target. Update consumers of newly written records together.

New readers retain legacy handling: an old record without the capability field defaults to True.
Restore continues to reconstruct recorded structure; this release does not serialize arbitrary
live application objects, their state or suspended execution.

### Compiled cache version advances from 7 to 8

The existing cache mismatch mechanism rebuilds plans compiled under the former default-injection
policy. No separate invalidation service or manual cache migration is introduced.

### Existing identity and ownership rules remain

- Omitted/True resolution capability preserves the existing binding fingerprint scheme;
  False uses a distinct fingerprint domain.
- Existing version rules remain: a same-identity method-body edit does not automatically create
  a new version. Use the normal registration/module/binding and version-selection workflows.
- Supplied existing objects retain the current unique-only model and existing disposal/transfer rules.
- The public distinction between a logical name and `spell_id=` **already existed in 0.2.37**.
  The benchmark changes repair stale callers; they are not a new addressing API in 0.2.43.

## Do not announce these as new in this release

**Already in the 0.2.37 baseline:** ordered live-spell disposal, the original Read the Docs
documentation rollout, and the human-name versus explicit-machine-ID Meld API. Their completed
records predate the baseline release. Current fixes/docs updates do not make those original features new.

**Not implemented by this release:**

- Named lesser conduits:
  naming, ConduitCloud registration and corresponding persistence remain design/discovery work.
- Purge:
  draft scope rules only; no purge runtime implementation.
- Existing-object lifecycle/ownership redesign:
  parked; multiple external-instance lifetimes, new disposal policy and ownership redesign are not delivered.
- Stateful application recovery:
  a proposed extension beyond structural restore, not a completed recovery feature.
- Broad shared-context rebuild/publication redesign:
  closed as cancelled/deferred, with its runtime repair unimplemented/unqualified. Do not convert
  that closure into a concurrency guarantee. The narrow cancellation fix above is a separate delivery.
